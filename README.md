# Web Board Games

Multiplayer browser board games on Cloudflare Workers. Each room is a Durable Object that owns the
WebSocket connections, the lobby and the running game.

Games: **Chess**, **Uno**, **Kingdomino**, **Dice**, **Rock Paper Scissors**, **Hamsterball**.

## Develop

```bash
npm install
npm run dev        # builds CSS, then http://localhost:8787
npm run build:css  # recompile public_html/tailwind.css after changing markup classes
npm test         # game-logic unit tests
npm run deploy
```

## Layout

| Path | What |
| --- | --- |
| `src/worker.js` | Entry point: `/ws` -> room Durable Object, `/api/*`, static assets |
| `src/durable-objects/GameRoom.js` | Lobby, identity, chat, host/kick, ready flow, game lifecycle |
| `src/games/*.js` | Server-side game logic (`config.js` is the game catalogue) |
| `public_html/` | Static client (`index.html`, `game.html`, `games/*`, `socket-client.js`, compiled `tailwind.css`) |
| `styles/tailwind.css` | Tailwind v4 entry; scans `public_html` and compiles to `public_html/tailwind.css` |
| `test/` | `node --test` unit tests for game logic |

## Adding a game

1. Add it to `src/games/config.js` (`available: true`) and the `GAME_CLASSES` map in `GameRoom.js`.
2. Implement a class with `constructor(room, players)`, `handleMessage(odId, type, payload)`,
   `cleanup()` and optionally `onPlayerLeft(odId)`. Call `room.endGame()` when it finishes.
3. Add `public_html/games/<id>.html` and `<id>.js` (the lobby loads them when the game starts).

## Notes

- Identity: a player id is paired with a private per-browser secret (`userSecret` in localStorage);
  the room stores only its hash, so ids shown in the player list can't be used to hijack a seat/host.
- A room resets (and forgets kicks) once the last player leaves. Games live in memory: if the
  Durable Object is evicted/restarted the room returns to the lobby.
- Kingdomino placement rules enforced server-side: in bounds, free cells, touching the existing kingdom.
  Terrain matching is not required (matches the client UI).

## SEO

- `index.html` carries the title/description, Open Graph + Twitter tags, JSON-LD (WebSite, WebApplication,
  ItemList of games, FAQPage), a single `<h1>`, crawlable game descriptions and an FAQ.
- Canonical and OG URLs are written site-relative with a `data-abs` attribute; the worker turns them
  into absolute URLs for whatever domain serves the page (`HTMLRewriter`).
- `/robots.txt` and `/sitemap.xml` are generated by the worker using the request origin.
- Room pages (`/game`, `/games/*`) are `noindex` (meta tag + `X-Robots-Tag` in `public_html/_headers`).
- Tailwind is precompiled (no runtime CDN script), fonts use `display=swap`, images/CSS have cache headers.
- The social preview image is `images/kingdomino.png`; swap in a 1200x630 image for better cards.

## Game notes

- Chess: full rules (castling, en passant, promotion, check/mate, stalemate, insufficient material,
  fifty-move, threefold). The engine is verified against standard perft counts (`npm test`).
- Uno: house rules - no +2/+4 stacking, a drawn card can be played at once, no challenge on +4.
- Dice: 5 rounds, two dice, highest total scores (ties share the point).
