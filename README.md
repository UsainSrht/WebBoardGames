# Web Board Games

Multiplayer browser board games on Cloudflare Workers. Every room is a Durable Object that owns the
WebSocket connections, the lobby and the running game.

Games: **Chess**, **Uno**, **Kingdomino**, **Dice**, **Rock Paper Scissors**, **Hamsterball**.

## Features

- Create a room, share the 6-character code, a link or a **QR code**; scan from the home page or any phone camera.
- **Host view**: the host can run the room without playing. They watch every game as a spectator and can pick,
  start, restart and end games, remove players and hand over the host role. Switch any time in the lobby.
- Reconnects automatically (network change, locked phone) and holds your seat; reloading mid-game restores the board.
- Responsive from phones to desktop (touch joystick in Hamsterball), view-transition page changes, reduced-motion support.
- Server-authoritative games, validated moves, rate-limited chat, private Uno hands.

## Develop

```bash
npm install
npm run dev          # builds CSS, then http://localhost:8787
npm run build        # compile public_html/tailwind.css and vendor the QR library
npm test             # unit tests (game logic, chess engine perft)
npm run test:e2e     # protocol test against a running `npm run dev` (PORT=8787 by default)
npm run deploy
```

## Layout

| Path | What |
| --- | --- |
| `src/worker.js` | Entry point: `/ws` to the room Durable Object, `/api/*`, robots/sitemap, canonical URL rewriting |
| `src/durable-objects/GameRoom.js` | Lobby, identity, roles, chat, host powers, game lifecycle (one `room-state` message keeps clients in sync) |
| `src/games/*.js` | Server-side game logic; `config.js` is the game catalogue (icons are names, not glyphs) |
| `public_html/index.html`, `index.js` | Home page: nickname, create / join / rejoin, QR scanner |
| `public_html/game.html`, `game.js` | Room page: lobby, drawer (people + chat), invite QR, game loader |
| `public_html/games/<id>.html/.js` | One UI fragment per game, loaded into the room page when a game starts |
| `public_html/core.js` | Shared client core: SVG icons, toasts, modals, QR rendering, preferences |
| `public_html/socket-client.js` | WebSocket wrapper with reconnect/heartbeat |
| `styles/tailwind.css` | Design system (Tailwind v4 tokens + components), compiled to `public_html/tailwind.css` |
| `public_html/vendor/` | Vendored browser libraries (copied by `scripts/vendor.mjs`) |
| `test/` | `node --test` unit tests and the e2e protocol test |

## Design rules

- **No emojis anywhere.** Use SVG icons: add them to `ICONS` in `public_html/core.js` and use
  `<i data-icon="name" class="size-5"></i>` or `WBG.icon('name', 'size-5')`. Chess pieces and dice faces are SVG too.
- Components (`.btn`, `.card`, `.input`, `.chip`, `.modal`, ...) live in `styles/tailwind.css`. Tailwind only generates
  classes it finds in `public_html`, so run `npm run build` after adding new ones.
- Everything the user sees must work on a phone first: 44px touch targets, 16px inputs, safe-area padding.

## Adding a game

1. Add it to `src/games/config.js` (`available: true`, an `icon` name from `core.js`) and `GAME_CLASSES` in `GameRoom.js`.
2. Implement a class with `constructor(room, players)`, `handleMessage(odId, type, payload)`, `cleanup()`, and optionally
   `onPlayerLeft(odId)` and `spectatorSync(odId)` (state for the host view). Call `room.endGame()` when it finishes.
3. Add `public_html/games/<id>.html` and `<id>.js`. Call `WBG.gameReady('<id>-page-loaded')` once loaded (spectators
   automatically get `spectate-ready` instead), use `socket.off(event)` before `socket.on(event)`, and register cleanup
   with `WBG.onTeardown(fn)`.

## SEO

- `index.html` carries the title/description, Open Graph + Twitter tags (1200x630 `og-image.png`), JSON-LD
  (WebSite, WebApplication, ItemList of games, FAQPage), a single `<h1>`, game descriptions and an FAQ.
- Canonical and OG URLs are site-relative with a `data-abs` attribute; the worker turns them into absolute URLs for
  whatever domain serves the page (`HTMLRewriter`). `/robots.txt` and `/sitemap.xml` are generated by the worker.
- Room pages (`/game`, `/games/*`) are `noindex` (meta tag + `X-Robots-Tag` in `public_html/_headers`).
- Tailwind is precompiled (no runtime script), fonts use `display=swap`, assets have cache headers.

## Notes

- Identity: a player id is paired with a private per-browser secret (`userSecret` in localStorage); the room stores only
  its hash, so ids shown in the player list can't be used to take over a seat or the host role.
- Rooms reset when the last player leaves, and abandoned rooms are wiped by a Durable Object alarm. Games live in
  memory: if the Durable Object restarts, the room returns to the lobby.
- Chess: full rules (castling, en passant, promotion, check/mate, stalemate, insufficient material, fifty-move,
  threefold) verified against standard perft counts.
- Uno: house rules - no +2/+4 stacking, a drawn card can be played at once, no challenge on +4.
- Kingdomino: placement must be in bounds, on free cells and touch the existing kingdom (terrain matching is not
  enforced, matching the UI). Every game event is logged so the host view and reloaded pages can replay it.
